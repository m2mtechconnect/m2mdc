## Route-boundary repair (done this checkpoint)

B7.4E left every legacy authenticated page (Layout, CoPilotProvider,
CoPilotCommandProvider, HealthBadges, GlobalSearchBar, useTokenRefresh,
and every page that invokes blocked edge functions) as **static** imports
at the top of `src/App.tsx`. That meant the /pilot/* initial JavaScript
chunk transitively contained all of those excluded capabilities, even
though PilotShell never rendered them. That is not a truthful pilot
boundary.

B7.4F repairs the boundary with two changes:

1. **`src/AuthenticatedShell.tsx` (new)** - a single lazy-loaded module
   that owns every legacy import: `Layout`, `CoPilotProvider`,
   `CoPilotCommandProvider`, `TourProvider`, `TourRenderer`, and all
   approved-user pages. Nothing outside this file may import it
   statically.
2. **`src/App.tsx`** - drops those static imports, deletes the
   `ApprovedUserLayout` / `ApprovedUserRoutes` inline wrappers, and
   mounts `AuthenticatedShell` via `React.lazy(...)` inside a `Suspense`
   boundary. `/pilot/*` continues to mount `PilotShell` directly (no
   Suspense hop, no legacy providers).

Net effect: on `/pilot/*` navigation, the browser downloads the pilot
chunk (PilotShell + PilotLayout + PilotOverview + PilotAssetInspection
+ pilotReadAdapter) and the shared root chunk. The
`AuthenticatedShell-*.js` lazy chunk (2.04 MB) is NOT fetched. That is
the isolation B7.4E claimed but did not enforce.
