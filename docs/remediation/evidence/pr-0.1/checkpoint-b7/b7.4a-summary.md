## Findings

1. **PILOT SCOPE UNDEFINED (Blocker).** `route-allowlist.json` declares four `production_routes`. One of them, `/reset-password`, is not a declared React route in `src/App.tsx` — the closest match is `/forgot-password`. A production request for `/reset-password` resolves to `<Navigate to="/" replace />`. The allowlist and the router disagree.
2. **UNAUTH ROUTER EXCEEDS ALLOWLIST.** The unauthenticated branch of `src/App.tsx` also exposes `/auth`, `/sign-in`, `/sign-up`, `/sign-out`, `/mfa`, `/twin-datacentre`, `/data-centre-twin`, `/omniverse-scene`, `/onboarding`. None are in `production_routes`; none are in `forbidden_production_routes`. They are silently production-reachable to anonymous users.
3. **AUTHED ROUTER FAR EXCEEDS ALLOWLIST.** The authenticated + approved branch declares ~50 additional routes (`/dashboard`, `/builder`, `/deploy`, `/agent/:id`, `/integrations`, `/marketplace`, `/admin/*`, `/connect/*`, etc.). These are the surfaces that transitively invoke every one of the 63 functions catalogued in `function-callsite-reconciliation.tsv`.
4. **NO PILOT FUNCTION IS REQUIRED.** The four documented pilot routes (`/`, `/login`, `/onboarding`, `/forgot-password`-as-declared) invoke zero edge functions. Authentication goes through the Supabase Auth SDK directly; onboarding writes via the Supabase client to `public.profiles`. `pilot_required_candidates = 0`.
5. **DRIFT VS B6.** B6 recorded 49 distinct invoked functions across 71 sites. Current trace shows 63 across 92 sites. New entries: `copilot-health`, `zapier-apps-list`, `zapier-apps-sync`, `zapier-app-connect`, `zapier-app-disconnect`, `zapier-oauth-connect`, `zapier-test-connection`, `knowledge-index`, `reco-selftest`, `workflow-run`, `funding-scraper`, plus extra call sites for `url-capture`, `url-recommendations`, `ops-overview`. One entry (`copilot-router`) is a README-only string, not a real call site.
6. **THREE FUNCTIONS ARE "TYPED-ACCESSIBLE-UNAVAILABLE" TODAY.** `health`, `copilot-health`, and `ops-overview` already render an accessible failure state on non-2xx. They are still not pilot-required.

## Why this is a stop condition

Per B7.4A rules, if more than five functions appear essential the checkpoint stops and reports. The inverse condition — zero required functions but hundreds of production-reachable non-pilot invocations behind routes the allowlist has not classified — is a materially worse scope mismatch and is also a stop condition. Reconciling 63 functions across 92 sites requires the pilot scope to first declare which of the ~55 undocumented production routes are (a) in scope and require function remediation, (b) explicitly forbidden, or (c) gated behind `import.meta.env.DEV` / feature flags.

## Requested decisions before B7.4A can be closed

1. **Reset the pilot route boundary.** Choose one:
   - Replace `/reset-password` with `/forgot-password` in `route-allowlist.json.production_routes`, OR
   - Add a real `/reset-password` page and route.
2. **Classify every route currently exposed by `src/App.tsx`** as `production_routes` OR `forbidden_production_routes` OR DEV-gated. Update the enforcer to reject unclassified routes (currently no rule enforces route classification — see NEG-A / NEG-D in `negative-tests-consolidated.json`).
3. **Confirm the pilot mode.** anonymous-only, approved-user-scoped subset, or full authenticated app. The candidate set of functions cannot be finalized until this is fixed.
