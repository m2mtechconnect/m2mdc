# Visual baseline repair

This branch is intentionally pinned to main at `b36349599272ed5354b2783518de6b0f69be5c40` so the screenshot baseline can be repaired independently from the P1 product changes.

## Why the prior baseline is stale

`tests/visual/approved-linux-visuals.json` names `96c474be47012020b18dd9570a06b4fcce24a07b` as its source. Current main is 187 commits ahead of that SHA and includes material changes to captured surfaces, including the shared layout, global CSS, navigation/workspace components and several captured pages. Those old hashes can no longer be treated as current visual truth.

Recent visual evidence also exposed a capture-contract defect: the approved analytics mobile screenshot was 375px wide while a fresh run produced a 425px-wide image without failing the existing overflow check.

## Repair contract

1. Mobile visual tests pin the CSS viewport and screen to 375x667 and devicePixelRatio to 1.
2. Responsive testing does not rely on Chromium mobile-layout heuristics to determine the visual baseline width.
3. Every mobile test asserts `window.innerWidth === 375` and `devicePixelRatio === 1` before screenshot capture.
4. Fresh exact-head screenshots are generated by CI and remain review evidence only. CI must never commit or approve its own baseline.
5. The fingerprint manifest is updated only after the generated artifact is reviewed for layout integrity, clipping, overflow and unintended content changes.
6. The refreshed manifest records the exact reviewed source SHA, workflow run, artifact id/digest and screenshot dimensions/hashes.

The branch is not merge-ready until the deterministic capture run completes and the reviewed manifest matches it exactly.
